# Financial and infrastructure skill audit

Read-only semantic audit of both `.claude/skills/` and `.codex/skills/` packages for `screen-targets`, `compare-peers`, `trace-grants`, `audit-contracts`, `build-infra`, `add-registry`, and `ingest-source`. All seven Codex bodies were read in full and the complete paired diffs inspected. Six pairs differ only in intended runtime syntax/frontmatter; `add-registry` has one additional inventory-update difference. The seven Codex bodies total 1,615 lines; none exceeds 500 lines. No production databases, source endpoints, audited workflows, or repository files were mutated. Validation used source inspection and isolated in-memory reproductions.

This report separates verified defects from modernization proposals. The parent owns current-source research; proposals below are repo-grounded candidates, not claims about official model guidance.

## Verified defects

### FI-1 — P2: Procurement finding example fails the current quote parser

- Location: [audit-contracts, lines 86–96](/Users/travcole/projects/osint-research/.codex/skills/audit-contracts/SKILL.md:86); identical Claude body at lines 87–97.
- The required HIGH-growth finding example supplies `--evidence "USASPENDING:<COMPANY>"` but `--source-quote "USASpending timeline data FY<YEARS>"`. The latter is neither a `ref:quote` pair nor an exact underlying data row.
- Verified implementation: [findings_tracker.py, lines 856–891](/Users/travcole/projects/osint-research/tools/findings_tracker.py:856) requires a colon-delimited evidence reference and raises on the example string. An isolated invocation of the exact parser functions, extracted with `ast` to avoid tracker initialization, produced: `ValueError Invalid quote metadata 'USASpending timeline data FY2024-2025'. Expected '<evidence_ref>:<value>'.`
- Realistic failure: the first promoted growth anomaly stops at persistence, or an agent repairs only the delimiter and persists method metadata as evidence. General evidence policy does not make this overtly incorrect runnable example correct.
- Small correction: use `USASPENDING:<stable-scope-ref>:<exact period/amount rows>` and put analytical method, cohort, query filters, retrieval date, and artifact path in detail. Verify with the existing parser and an isolated tracker fixture.

## Modernization proposals (not verified execution failures)

### 1. Make heuristic thresholds reviewable defaults, not automatic findings policies

- [screen-targets, lines 124–168](/Users/travcole/projects/osint-research/.codex/skills/screen-targets/SKILL.md:124) hardcodes 3/2/1 weights, score-based lead creation, and “Clean” for scores 0–1; [audit-contracts, lines 73–96](/Users/travcole/projects/osint-research/.codex/skills/audit-contracts/SKILL.md:73) treats fixed 25%/50% growth cutoffs and an asserted typical 5–15% sector rate as general; [trace-grants, lines 73–76](/Users/travcole/projects/osint-research/.codex/skills/trace-grants/SKILL.md:73) requires findings for every reciprocal pair, the top five edges, and each node with both directions.
- Keep scoring for sorting and reproducibility, but identify its version, calibration domain and limits. Use “no screened flags” rather than an unqualified “Clean”; separate unavailable/missing ratios from tested metrics. Let evidence relevance, business model and research question determine promotion, with a short explanation of deviations from defaults. A high anomaly count is not itself forensic significance.
- This is not a proposal to remove falsification, innocent explanations, exact evidence or confidence limits. Those constraints protect the output. Evaluate a revised flow on low-margin legitimate businesses, fast-growing small contractors, incomplete financial coverage, normal fiscal sponsorship, and a clear positive control before changing defaults.

### 2. Move deterministic orchestration and coverage reporting into reusable CLI capabilities

- [screen-targets:204](/Users/travcole/projects/osint-research/.codex/skills/screen-targets/SKILL.md:204) anticipates about 100 tool invocations for 20 companies, while [lines 74–87](/Users/travcole/projects/osint-research/.codex/skills/screen-targets/SKILL.md:74) repeats lookup, three statement extractions and calculation. [compare-peers, lines 49–74](/Users/travcole/projects/osint-research/.codex/skills/compare-peers/SKILL.md:49) duplicates the pipeline.
- A tested batch statement/ratio command could resolve each filing once, produce bounded summaries plus full artifacts, expose failed/missing metrics and respect rate limits. Skill prose should retain selection and interpretation. Do not create an opaque “do the whole investigation” wrapper; preserve independently inspectable evidence artifacts and per-target failure status.
- Likewise `trace-grants` hydration should use exactly the discovery filters. The instruction at [lines 105–111](/Users/travcole/projects/osint-research/.codex/skills/trace-grants/SKILL.md:105) names recipient EIN and years; actual flow SQL also filters **individual** `cash_amount >= min_amount` ([query_990.py:1227](/Users/travcole/projects/osint-research/tools/query_990.py:1227)). Mixed small/large grants otherwise force an avoidable reconciliation. Keep the existing sum/count reconciliation; automate it rather than relaxing it.

### 3. Expose the tool's actual analytical scope before writing more interpretation rules

- `compare_multiple` silently chooses each company's latest period independently at [financial_ratios.py, lines 481–492](/Users/travcole/projects/osint-research/tools/financial_ratios.py:481), returns `latest_periods` at [line 574](/Users/travcole/projects/osint-research/tools/financial_ratios.py:574), but the skill's result-field guide at [compare-peers, lines 76–85](/Users/travcole/projects/osint-research/.codex/skills/compare-peers/SKILL.md:76) and output matrix omit it. Surface periods, complete versus partial years, and currency/unit comparability; select aligned periods or explicitly qualify exclusions before interpreting outliers. A fixture with different latest years would exercise this.
- `trace-grants` documents depth and minimum amount but not `flow`'s default **50 edges per queried node/hop**, odd-depth outgoing/even-depth incoming traversal, or reverse-flow augmentation. Those are implemented at [query_990.py:1220](/Users/travcole/projects/osint-research/tools/query_990.py:1220), [1243](/Users/travcole/projects/osint-research/tools/query_990.py:1243), [1269](/Users/travcole/projects/osint-research/tools/query_990.py:1269), and [1557](/Users/travcole/projects/osint-research/tools/query_990.py:1557). “Depth 2” does not mean a complete two-hop downstream flow trace. Add these scope facts and truncation/frontier metadata to tool output; let the skill choose additional traversal only when the question needs it.

### 4. Give source onboarding one canonical implementation contract with specialized entry points

- `build-infra`, `add-registry`, and `ingest-source` share endpoint discovery, implementation, testing and inventory updates but drift in useful requirements. [build-infra, lines 127–132](/Users/travcole/projects/osint-research/.codex/skills/build-infra/SKILL.md:127) includes rate limiting, retry handling, output and search logging; [ingest-source, lines 60–73](/Users/travcole/projects/osint-research/.codex/skills/ingest-source/SKILL.md:60) focuses on bounded output; the registry scaffold omits both sets. Build-infra's completion checklist at [lines 189–195](/Users/travcole/projects/osint-research/.codex/skills/build-infra/SKILL.md:189) is fuller than the other two.
- Put stable output/failure contracts, source catalog/citation/health registration, tests, fixture retention and dependency handling in one linked source-adapter guide or scaffold. Keep queue claim/evaluation in build-infra, source-format onboarding in ingest-source, registry schema/identity rules in add-registry. Add activation boundaries to their descriptions so the agent can choose among them without loading all three.
- Replace ingest-source's environment-ambiguous `pip install datasets` ([line 27](/Users/travcole/projects/osint-research/.codex/skills/ingest-source/SKILL.md:27)) with the project dependency workflow or an explicitly isolated temporary dependency command. `datasets` is not in `pyproject.toml`; a global `pip` installation does not define the `uv run` environment reproducibly.

### 5. Prefer canonical discovery over copying each new tool into every workflow skill

- [build-infra:194](/Users/travcole/projects/osint-research/.codex/skills/build-infra/SKILL.md:194) requires updating every workflow skill that should call a newly introduced tool in both trees. This creates a multiplying maintenance surface. Skills can point to the canonical source/module catalog and task-specific applicability criteria, while inline examples cover only stable, frequently needed operations.
- Do not split these seven bodies solely to meet a line-count target: all are already under 500 lines. Prioritize reducing genuinely duplicated source-onboarding templates and fixed report scaffolds, not moving a short self-contained skill behind extra navigation.
- Replace generic Codex default prompts such as “handle this investigation task with clear evidence and actionable output” with concrete expected input/output cues, and move “Tier 0/Tier 2/Analysis Plane” out of the scarce description space where ordinary user language would improve discovery. Validate with realistic positive and negative trigger prompts before changing activation behavior.

- `build-infra` probes before coding, preserves useful paid/registered/human access routes, distinguishes blocked from invalid sources, and audits raw occurrence grain before projecting joins ([lines 62–117](/Users/travcole/projects/osint-research/.codex/skills/build-infra/SKILL.md:62)).
