# Platform hardening closeout

The implementation follows the [component review](../platform-review-2026-09-05/review.md) and its [46-item requirement ledger](../../docs/PLATFORM_HARDENING_PLAN.md). Code, workflow, test, and repository changes are on `codex/platform-hardening-20260905`. Commits are local; no push, merge, deployment, or research-subject contact was performed.

## What changed

- Findings and staged imports share a transaction-aware writer with required quoted evidence, confidence limits, normalized dates, and canonical subject links. Claim corrections invalidate stale verification. Identity resolution checks jurisdiction, type, and strong identifiers. Fresh and historical schemas preserve provenance and foreign keys; initialization is scoped to the actual database.
- Queue jobs, triggers, workers, and children retain their selected investigation and database. Imports check the exact reviewed artifacts and replay atomically. Durable exit receipts, launch reservations, deadlines, process-group cleanup, and terminal-state guards prevent false completion and duplicate work. Acquisition outcomes remain separate from answering a research question.
- Registry refreshes retain stable identities and history. Public-record adapters preserve parcel years, owner labels, selector errors, and continuation state. USAspending writes explicit success/partial/failure artifacts. FEC history retains query scope. A content-keyed catalog parse cache removes repeated YAML parsing without caching validation or access decisions.
- Publication uses a selected content tree and an authoritative versioned finding snapshot. Graphs retain each claim's own provenance and profile; visualization updates preserve authored prose. Local and CI release commands validate the same artifact before deployment. Article metadata has one schema-aware loader. Search recovers from failed loading, supports typing before readiness, and restores focus; visualization modules load on demand and tooltips treat data as text.
- Shared research instructions require exact-version semantic review, usable and fresh search artifacts, neutral alternatives, applicable sources, audited date corrections, and a clear distinction between confidence ceilings and proposition probability.
- Deterministic CI includes pytest and unittest cases, rejects external network access, and guards representative integrity tests against accidental deselection. Supported runtime dependencies and browser-check fixtures are explicit.

## Publication and execution limits

The actual release command correctly stops at existing content debt. The retained [diagnostic summary](validation/current-publication-diagnostics-summary.json) covers 534 source files and reports 32,446 issue occurrences/references, **not distinct findings**. Only 116 finding IDs qualified for the in-memory candidate under the current checks; no candidate snapshot or deploy artifact was produced. Missing/unquoted evidence, invalid source metadata, over-cap claims, conflicting copies, and a missing authoritative snapshot require evidence-preserving content work. Existing semantic review receipts must also match the exact content version. No historical facts, quotations, confidence/status values, or semantic PASS receipts were invented to clear the gate. A separately committed [link-only repair](validation/pesner-source-link-repair.json) replaced 19 obsolete source anchors in the Steven Pesner dossier with supported citation syntax for the same 11 document IDs; structural comparison verified that surrounding prose and research metadata were unchanged. This content version still requires semantic review.

A static snapshot is authority for a reviewed content version; it is not continuous synchronization with the live database. A correction or retraction requires an audited candidate refresh and renewed content review. The explicit database audit validates current provenance before comparing fingerprints. Older schema-1 exports may omit source metadata; supplied metadata is validated, and current database audit rows require it. Structural checks and review receipts establish consistency and version binding, not the truth of a claim.

Staged research uses the documented prompt contract and still has workspace/tool access; it is not an operating-system sandbox. Cost limits are soft, in-process cancellation is cooperative, and intentionally detached processes are outside normal group cleanup. Legacy runs lacking exit receipts fail closed; old unpinned research queue jobs require explicit re-enqueueing. See the [execution contract](../../docs/EXECUTION_CONTRACT.md).

The representative adapter cleanup does not claim to replace every legacy wrapper or verify live endpoint health. Historical orphan/identity repairs need recoverable evidence. The unrelated user-shell `fnm` startup papercut remains outside repository scope.

Those files remain local and ignored, with no evidence deletion.

The [Git workflow policy](../../docs/GIT_WORKFLOW.md) requires an owned workstream branch, coordinated files or separate worktrees, explicit staging, relevant validation, and focused commits. Local hooks and independent CI check staged/committed blobs for prohibited artifacts, credential patterns, size limits, protected branch use, and commit-message structure. Existing Git LFS hooks were preserved. These pattern checks supplement deliberate review; they are not a comprehensive secrets audit.

All task-owned implementation, link repair, and closeout artifacts are recorded in focused local commits. [Commit inventory](validation/implementation-commits.json) separates inherited recovery from implementation; this closeout document is committed with the final validation records.
